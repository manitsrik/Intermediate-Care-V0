ระบบตัดสินให้เองว่าผู้ป่วยรายนี้ควรเข้าโปรแกรม IMC หรือไม่ จากสองเงื่อนไข คือคะแนน BI ต่ำกว่า 15 หรือได้ 15 ขึ้นไปแต่มีความบกพร่องหลายด้านร่วมกัน (multiple impairment เช่น ทั้งเดินลำบากและกลืนลำบาก)

รายที่ยังไม่มีใครไปประเมินจะขึ้นว่า ยังไม่ประเมิน ซึ่งไม่เท่ากับ "ไม่เข้าเกณฑ์" คนละเรื่องกัน กลุ่มนี้คือคนที่ยังไม่มีคำตอบ ไม่ใช่คนที่ได้คำตอบว่าไม่เข้า กรองเอามาดูได้จากช่องผลคัดกรองในหน้ารายชื่อผู้ป่วย

dc_reason

เหตุผลที่ผู้ป่วยจบโปรแกรม เลือกจากรายการตายตัว 8 แบบ ไม่ใช่พิมพ์เอง เช่น BI > 15 · ไม่มาตามนัด · กลับมาทำงานได้ · เสียชีวิต เป็นช่องบังคับกรอกตอนกดจบโปรแกรม ข้อมูลจึงครบทุกเคสที่ปิดผ่านแอป

แท่งสรุปในหน้ารายงานนับเฉพาะเคสที่ปิดแล้ว หัวข้อจึงบอกฐานไว้ด้วย เช่น "จาก 32 รายที่จบแล้ว" กันอ่านเปอร์เซ็นต์ผิดว่าเป็นสัดส่วนของผู้ป่วยทั้งหมด

งานค้าง

กล่อง "ต้องจัดการ" · ป้ายบนแถวรายชื่อ

ตัวเลขบนการ์ดบอกว่าสถานการณ์เป็นอย่างไร แต่ไม่บอกว่าวันนี้ต้องหยิบเคสไหนขึ้นมาทำ กล่องนี้จึงรวมเคสที่ค้างไว้ แยกบรรทัดตามเหตุผล กดแล้วเปิดรายชื่อกลุ่มนั้นได้ทันที

บรรทัดป้ายบนแถวหมายถึง
เลยกำหนดนัดแล้วเลยนัด (ส้ม)วันนัดผ่านไปแล้วแต่เคสยังไม่ปิด
ครบกำหนดโปรแกรมแล้วครบกำหนด (ส้ม)ครบ 6 เดือนแล้วแต่ยังไม่ปิดเคส
ไม่ได้ประเมิน BI เกิน 8 สัปดาห์ค้างประเมิน BI (ส้ม)เคสกำลังหลุดมือ ไม่รู้ว่าดีขึ้นไหม
คัดกรองออกแล้ว ยังไม่ปิดเคสต้องปิดเคส (ส้ม)ไม่เข้าเกณฑ์แต่ลืมปิด ทำให้ยอดกำลังดูแลสูงเกินจริง
ปิดเคสแล้วแต่ไม่มีวันสิ้นสุดไม่มีวันสิ้นสุด (เทา)ส่วนใหญ่มาจากข้อมูลนำเข้า ทำให้หายไปจากกราฟ

ห้าข้อแรกนับเฉพาะเคสที่ยังไม่ปิด ส่วนข้อสุดท้ายกลับกัน นับเฉพาะเคสที่ปิดไปแล้ว บรรทัดที่ยอดเป็นศูนย์จะไม่แสดง ถ้าไม่ค้างเลยกล่องจะบอกว่าไม่มีงานค้าง

เลยกำหนดนัดแล้ว หายไปเมื่อวันนัดถูกเลื่อนไปข้างหน้า วิธีที่ตรงที่สุดคือ กรอกช่อง นัดครั้งถัดไป ในฟอร์มบันทึกการติดตาม ตามคนไข้เสร็จแล้วเลื่อนนัด ตรงนั้นที่เดียว งานค้างข้อนี้จะหายไปเอง ไม่ต้องเข้าไปแก้เวชระเบียนแยกอีกที และรายชื่อชุดเดียวกันนี้ขึ้นอยู่บนสุดของหน้าการติดตาม ในกล่อง "ถึงกำหนดต้องตาม"

ธงชุดเดียวกันนี้ไปโผล่เป็นป้ายท้ายแถวในหน้ารายชื่อผู้ป่วยด้วย ที่นั่นใช้คำสั้นเพราะช่องแคบ เอาเมาส์วางบนป้ายแล้วเห็นคำเต็ม กล่องบนแดชบอร์ดตอบว่า ค้างกี่ราย ส่วนป้ายบนแถวตอบว่า รายที่กำลังดูอยู่นี้ค้างอะไร และกรองเอาเฉพาะรายที่ค้างมาดูได้จากดรอปดาวน์งานค้าง

สีของป้ายมีความหมาย สี่ข้อแรกเป็นสีส้ม แปลว่ากระทบคนไข้ที่ยังดูแลอยู่ ต้องลงมือวันนี้ ส่วน "ไม่มีวันสิ้นสุด" เป็นสีเทา เพราะเป็นช่องที่ไล่เติมจากแฟ้มเก่า ตอนว่างได้ ไม่กระทบการดูแล ของจริงมีเคสเก่าแบบนี้อยู่เกือบทุกแถว ถ้าย้อมส้มไปด้วยทั้งหมด ตาจะเลิกมองป้ายแล้วรายที่ต้องรีบจริงจะหายไปกลางกอง ด้วยเหตุนี้บรรทัดใต้ชื่อหน้ารายชื่อจึงแยกนับเป็น มีงานค้าง กับ ข้อมูลต้องเติม คนละก้อน

ครบ 6 เดือน

183 วันนับจากวัน Start

ระยะเวลาของโปรแกรม IMC ระบบนับจากวันที่เริ่มโปรแกรมไป 183 วันพอดี แล้วบอกวันที่จะครบให้อัตโนมัติ ไม่ต้องนั่งนับปฏิทินเอง

วัน Start

คนละวันกับวัน admit

วันที่เริ่มเข้าโปรแกรม IMC ซึ่งไม่ใช่วันที่เข้านอนโรงพยาบาล (admit) และไม่ใช่วันจำหน่าย (discharge หรือ D/C) ระบบใช้วันนี้เป็นตัวตั้ง ทั้งการเรียงลำดับรายชื่อ การนับกราฟรายเดือน และการนับครบ 6 เดือน

Dx

Diagnosis · การวินิจฉัย

โรคหรือภาวะที่เป็นเหตุให้เข้าโปรแกรม ในระบบมีให้เลือกเป็นรายการ เช่น Ischemic stroke (สมองขาดเลือด), Hemorrhagic stroke (เลือดออกในสมอง), TBI (บาดเจ็บสมอง), SCI (บาดเจ็บไขสันหลัง)

ที่ต้องเลือกจากรายการแทนการพิมพ์เอง เพราะถ้าคนหนึ่งพิมพ์ว่า "Ischemic stroke" อีกคนพิมพ์ "ischemic Stroke" ระบบจะนับเป็นคนละโรค แล้วรายงานจะผิด

HN

Hospital Number

เลขประจำตัวผู้ป่วยของโรงพยาบาล ระบบใช้เลขนี้เป็นตัวเชื่อมข้อมูลทุกอย่าง ทั้งประวัติ ผลประเมิน BI และบันทึกการติดตาม จึงห้ามซ้ำกันเด็ดขาด ถ้าลงทะเบียน HN ที่มีอยู่แล้ว ระบบจะเตือนและไม่ให้บันทึก

Google กับ Apps Script

หมวดนี้คือคำที่จะได้ยินตอนคุยกับฝ่าย IT หรือตอนที่มีอะไรพัง รู้ไว้พอให้อธิบายอาการได้ถูกจุด

Google Apps Script

ตัวรันโปรแกรมของ Google

บริการฟรีของ Google ที่ให้เขียนโปรแกรมผูกกับไฟล์ Google Sheets ได้ แอปนี้ทั้งแอปรันอยู่บนนี้ ไม่มีเซิร์ฟเวอร์ของตัวเอง ไม่มีค่าเช่ารายเดือน และไม่ต้องมีคนคอยดูแลเครื่อง

Web App

หน้าเว็บที่ทีมเปิดใช้

หน้าจอที่เห็นทั้งหมดคือ Web App ที่ Apps Script สร้างขึ้นมา ทีมเปิดผ่านลิงก์เดียวกันทุกคน ไม่ต้องติดตั้งอะไรลงเครื่อง ใช้ได้ทั้งคอมพิวเตอร์และมือถือ

Deploy

การเผยแพร่เวอร์ชันใหม่

การทำให้ของที่แก้เสร็จแล้วขึ้นไปอยู่บนลิงก์ที่ทีมใช้จริง ทุกครั้งที่ deploy จะได้เลขเวอร์ชันใหม่ ตอนนี้อยู่ที่ v50

สำคัญ: แก้โค้ดเสร็จแล้วยังไม่พอ ถ้ายังไม่ deploy ทีมจะยังเห็นของเก่าอยู่ และหลัง deploy บางครั้งต้องกด Ctrl+Shift+R หนึ่งครั้ง เพื่อบังคับให้เบราว์เซอร์โหลดไฟล์ใหม่ ไม่ใช้ของที่จำไว้

ลิงก์ /exec กับ /dev

ตัวจริง กับ ตัวทดลอง

ลิงก์ที่ลงท้ายด้วย /exec คือตัวจริงที่ทีมใช้ เห็นเฉพาะเวอร์ชันที่ deploy แล้ว ส่วน /dev คือตัวทดลอง เห็นโค้ดล่าสุดทันทีโดยไม่ต้อง deploy แต่เปิดได้เฉพาะเจ้าของสคริปต์

ลิงก์ที่แจกทีมต้องเป็น /exec เสมอ

สิทธิ์สองชั้น

สิทธิ์ในแอป · สิทธิ์แก้ไขไฟล์

ผู้ใช้แต่ละคนต้องมีสองอย่างพร้อมกันถึงจะทำงานได้ หนึ่งคือมีชื่ออยู่ในรายชื่อผู้ใช้ของแอป สองคือมีสิทธิ์แก้ไขไฟล์ Sheet เพราะแอปสั่งให้แต่ละคนเขียนข้อมูลด้วยบัญชีของตัวเอง

ระบบจัดการสองอย่างนี้พร้อมกันให้แล้ว กดเพิ่มผู้ใช้จะแชร์ไฟล์ให้อัตโนมัติ กดปิดการใช้งานจะถอนสิทธิ์ไฟล์ให้ด้วย ถ้าไม่ถอน คนที่ถูกปิดยังเปิดไฟล์ดิบ อ่านข้อมูลผู้ป่วยได้อยู่

คอลัมน์ การเข้าถึงไฟล์ ในตารางผู้ใช้คือชั้นที่สองนี้ ปกติขึ้นว่า แชร์แล้ว ถ้าขึ้นเป็นสีเตือนแปลว่าสองชั้นไม่ตรงกัน เช่นปิดสิทธิ์ในแอปแล้ว แต่ยังเปิดไฟล์ได้ ตรงนั้นจะมีปุ่มให้กดแก้ทันที

สิ่งที่มันไม่ทำ มันไม่ปิดบังข้อมูลที่กรอกผ่านแอป ถ้าลงทะเบียนเคสใหม่ตอนนี้ ชื่อจริงกับเบอร์จริงลงชีตเต็ม ๆ ทันที ไม่ว่าโหมดนี้จะเปิดหรือปิด การปิดบังมีอยู่ที่เดียวคือตอนนำเข้าจากไฟล์เก่า และมันไม่ย้อนของที่นำเข้าไปแล้ว เพราะข้อมูลถูกปิดบังตั้งแต่ตอนเขียนลงชีต ชื่อจริงไม่เคยถูกเก็บ ปิดโหมดทีหลังจึงไม่ได้คืนอะไรให้

พูดสั้น ๆ คือ เป็นป้ายบอกสถานะ ไม่ใช่เกราะกันข้อมูลรั่ว

ไฟล์ CSV กับ BOM

ไฟล์ที่เปิดด้วย Excel

CSV คือไฟล์ตารางแบบง่ายที่สุด เปิดด้วย Excel ได้เลย ส่วน BOM คือเครื่องหมายเล็ก ๆ ที่ซ่อนอยู่หัวไฟล์ บอก Excel ว่าข้างในเป็นภาษาไทย

ถ้าไม่มี BOM Excel บนวินโดวส์จะอ่านภาษาไทยเป็นตัวขยะทั้งไฟล์ เป็นจุดที่พลาดกันบ่อยเพราะถ้าทดสอบด้วย Google Sheets จะไม่เจอปัญหานี้เลย

เจอที่ ปุ่ม Excel ในกล่องรายชื่อ

commit กับ push

การเก็บประวัติโค้ด

commit คือการบันทึกสภาพของโค้ด ณ จุดหนึ่งไว้ในเครื่อง พร้อมข้อความอธิบายว่าแก้อะไรไปบ้าง ทำให้ย้อนกลับไปจุดไหนก็ได้ push คือการส่งสิ่งที่ commit ไว้ขึ้นไปเก็บที่ GitHub เพื่อให้มีสำเนาอยู่นอกเครื่อง

สามคำนี้คนละเรื่องกัน ทำอย่างหนึ่งไม่ได้แปลว่าอีกอย่างเกิดขึ้นด้วย

คำสั่งผลที่เกิด
commitบันทึกประวัติไว้ในเครื่อง ทีมยังไม่เห็นอะไร
pushส่งประวัติขึ้น GitHub มีสำเนานอกเครื่อง
deployทีมเห็นของใหม่บนลิงก์จริง

พรีวิวบนเครื่อง

preview

ไฟล์จำลองหน้าตาแอปที่เปิดดูบนเครื่องได้เลยโดยไม่ต้อง deploy ใช้ข้อมูลปลอมทั้งหมด ไม่แตะข้อมูลผู้ป่วยจริง มีไว้ให้ดูหน้าตาก่อนว่าถูกใจไหม จะได้ไม่ต้องเอาของที่ยังไม่แน่ใจขึ้นไปให้ทีมเห็น

ปกติเปิดไฟล์บนคอมได้เลย ถ้าอยากดูจากมือถือเครื่องจริงในวงแลนเดียวกัน ต้องเปิดผ่านเซิร์ฟเวอร์เล็ก ๆ บนคอมก่อน แล้วพิมพ์เลข IP ที่มันบอกลงมือถือ
