# ระบบบันทึกข้อมูลผู้ป่วย Intermediate Care

เว็บแอปให้บุคลากรกรอกแบบฟอร์มประเมินและดูแลผู้ป่วยในโปรแกรม Intermediate Care
โดยเก็บข้อมูลลง Google Sheet ของหน่วยงานโดยตรง สร้างด้วย Google Apps Script
จึงไม่ต้องเช่าเซิร์ฟเวอร์ และข้อมูลผู้ป่วยไม่ออกจากบัญชี Google ของโรงพยาบาล

อ้างอิงจากแบบฟอร์มกระดาษของกลุ่มงานเวชกรรมฟื้นฟู โรงพยาบาลกระบี่
(หน้า 1 ข้อมูลผู้ป่วยและตารางติดตาม หน้า 2 แบบประเมิน Barthel Index)

## สิ่งที่อยู่ในโฟลเดอร์

| ไฟล์ | หน้าที่ |
|---|---|
| `apps-script/Config.gs` | ค่าตั้งต้นทั้งหมด รวมถึงสวิตช์โหมดทดสอบ และเนื้อหาแบบประเมิน BI 10 ข้อ |
| `apps-script/Schema.gs` | โครงสร้างชีต ฟังก์ชันติดตั้งระบบ และชีต summary ที่สร้างจากสูตร |
| `apps-script/Util.gs` | แปลงวันที่ไทย ปกปิดข้อมูล PDPA อ่านเขียนชีต และ lock กันบันทึกชนกัน |
| `apps-script/Bi.gs` | คิดคะแนน Barthel Index เกณฑ์เข้า IMC และจัดกลุ่ม CTF |
| `apps-script/Api.gs` | ฟังก์ชันที่หน้าเว็บเรียกใช้ ตรวจสิทธิ์ผู้ใช้ และคำนวณค่าสรุป |
| `apps-script/Migrate.gs` | นำเข้าข้อมูลเดิม 55 เคส พร้อมแก้วันที่เพี้ยนและรายงานจุดที่ต้องตรวจซ้ำ |
| `apps-script/WebApp.gs` | จุดเข้าเว็บแอป |
| `apps-script/index.html`, `css.html`, `js.html` | หน้าจอทั้งหมดของแอป |
| `tests/test-dates.js` | ทดสอบตรรกะแปลงวันที่กับค่าจริงจากไฟล์เดิม รันด้วย `node tests/test-dates.js` |
| `tests/test-render.js` | วาดทุกหน้าจอด้วยข้อมูลจำลองเพื่อดูว่าไม่พัง รันด้วย `node tests/test-render.js` |
| `tests/test-preboot.js` | ตรวจการเปิดแอปแบบไม่ต้องรอเซิร์ฟเวอร์ และพฤติกรรมตอนเน็ตหลุด รันด้วย `node tests/test-preboot.js` |
| `tests/test-pwa.js` | ตรวจว่าเปลือก PWA ยังเข้าเกณฑ์ติดตั้งของ Chrome รันด้วย `node tests/test-pwa.js` |
| `pwa/` | เปลือก PWA สำหรับวางบน GitHub Pages ให้ Android ติดตั้งลงหน้าจอโฮมได้ |
| `tools/make-icons.js` | สร้างไอคอนแอปทุกขนาดจากเครื่องหมายในแอป ไม่ต้องมีโปรแกรมแต่งรูป |
| `tools/serve-pwa.js` | เปิดเซิร์ฟเวอร์บนเครื่องเพื่อทดลองเปลือก PWA ก่อน push |

## ขั้นตอนติดตั้ง

1. สร้าง Google Sheet ใหม่ในบัญชี Google ที่จะใช้เก็บข้อมูล ตั้งชื่อเช่น `IMC Database`
2. วางข้อมูลเดิมจากไฟล์ `ตยเคส.xlsx` เป็นแท็บชื่อ **ตยเคส** ในไฟล์เดียวกัน (ถ้าจะนำเข้าข้อมูลเก่า)
3. เปิดเมนู **ส่วนขยาย → Apps Script**
4. สร้างไฟล์ตามรายการข้างบนแล้วคัดลอกเนื้อหาไปวางให้ครบ
   - ไฟล์ `.gs` สร้างเป็น Script ส่วนไฟล์ `.html` สร้างเป็น HTML
   - `appsscript.json` แก้ได้โดยเปิด **การตั้งค่าโปรเจกต์** แล้วติ๊ก *แสดงไฟล์ appsscript.json*
5. บันทึก แล้วกลับไปที่ Google Sheet **โหลดหน้าใหม่หนึ่งครั้ง** จะเห็นเมนู **Intermediate Care**
6. เลือก **Intermediate Care → ติดตั้งระบบ (ครั้งแรก)** ระบบจะสร้างชีตทั้งหมดให้
7. กลับไปที่ Apps Script เลือก **ทำให้ใช้งานได้ → การทำให้ใช้งานได้ใหม่ → เว็บแอป**
8. คัดลอกลิงก์เว็บแอปไปให้ทีมใช้งาน
9. แชร์ไฟล์ Google Sheet ให้ทีมทั้ง 5 คนในสิทธิ์ **ผู้แก้ไข**

### เรื่องสิทธิ์ของ deployment

`appsscript.json` ตั้งไว้เป็น `executeAs: USER_ACCESSING` และ `access: ANYONE`
เพราะช่วงทดสอบใช้บัญชี Gmail ส่วนตัวซึ่งไม่มีตัวเลือก "ทุกคนในองค์กร"

- แต่ละคนจะรันสคริปต์ด้วยบัญชีตัวเอง ระบบจึงบันทึกได้ถูกต้องว่าใครเป็นผู้กรอก
- ด้วยเหตุนี้ทุกคนต้องได้สิทธิ์ **ผู้แก้ไข** บนไฟล์ Sheet ด้วย
- `access: ANYONE` หมายถึงใครก็ตามที่มีลิงก์และล็อกอิน Google เปิดหน้าเว็บได้
  แต่จะใช้งานไม่ได้ถ้าอีเมลไม่อยู่ในแท็บ `users` ระบบจะปฏิเสธและแจ้งกลับไป

เมื่อย้ายไปบัญชี Google Workspace ของโรงพยาบาล ให้เปลี่ยนเป็น
`executeAs: USER_DEPLOYING` และ `access: DOMAIN` แล้ว deploy ใหม่
ทีมจะไม่ต้องมีสิทธิ์แก้ไขไฟล์ Sheet โดยตรงอีกต่อไป ซึ่งปลอดภัยกว่าสำหรับข้อมูลจริง

ถ้าถนัดใช้ command line ติดตั้ง [clasp](https://github.com/google/clasp) แล้วสั่ง
`clasp create --type sheets` และ `clasp push` จากโฟลเดอร์ `apps-script` ได้เช่นกัน

## การให้สิทธิ์ผู้ใช้

เพิ่มอีเมลของทีมในแท็บ `users` คอลัมน์ `email` และใส่ `TRUE` ในคอลัมน์ `active`
ตอนนี้ทุกคนสิทธิ์เท่ากันหมด (`role` = `staff`) ถ้าภายหลังต้องแยกสิทธิ์ผู้ดูแล
ให้เพิ่มการตรวจ `role` ในฟังก์ชัน `currentUser_` ที่ `Api.gs`

ถ้ายังไม่มีใครในตาราง `users` เลย ระบบจะอนุญาตให้ทุกคนที่เปิดไฟล์ได้ใช้งานไปก่อน
เพื่อให้ติดตั้งครั้งแรกได้ พอเพิ่มรายชื่อแล้วจะบังคับตรวจสิทธิ์ทันที

## โหมดทดสอบและ PDPA

`CONFIG.MASK_MODE` ใน `Config.gs` ตั้งไว้เป็น `true` ตอนนี้ หมายความว่า

- ตอนนำเข้าข้อมูลเดิม ชื่อจะกลายเป็น `ทดสอบ 1`, `ทดสอบ 2`
  HN กลายเป็น `TEST001`, `TEST002` ที่อยู่กลายเป็น `xxx`
  เบอร์โทรเหลือ 3 ตัวแรกแล้วต่อด้วย `xxx-xxxx`
- หน้าเว็บจะขึ้นแถบเตือนสีเหลืองว่ากำลังใช้ข้อมูลสมมติ

เมื่อจะใช้งานจริง

1. ย้ายไฟล์ไปอยู่ใน Shared Drive หรือบัญชี Google Workspace ของโรงพยาบาล
2. แจ้งผู้รับผิดชอบข้อมูลส่วนบุคคลของโรงพยาบาลให้รับทราบก่อนเริ่มเก็บข้อมูลจริง
3. จำกัดสิทธิ์การเข้าถึงไฟล์เป็นรายบุคคล อย่าใช้ตัวเลือก "ทุกคนที่มีลิงก์"
4. เปลี่ยน `MASK_MODE` เป็น `false` แล้ว **ล้างข้อมูลทดสอบออกก่อน**
   ด้วยเมนู **Intermediate Care → ล้างข้อมูลที่นำเข้ามา**

## การนำเข้าข้อมูลเดิม

เลือกเมนู **Intermediate Care → นำเข้าข้อมูลเดิมจากชีต ตยเคส**

ไฟล์เดิมมีปัญหาที่ตัวนำเข้าจัดการให้อัตโนมัติ

- **วันที่เพี้ยนเป็นปี ค.ศ. 19xx** เพราะพิมพ์ปี พ.ศ. สองหลักแล้วโปรแกรมตีความเป็น ค.ศ.
  เช่นเลข `25132` คือ 21 ต.ค. 1968 ระบบจะแปลงกลับเป็น 21 ต.ค. 2568
- **รูปแบบวันที่ปนกันหลายแบบ** ทั้งเลข serial, `27/10/68` และ `01 พฤษภาคม 2569`
- **ข้อมูลอยู่ผิดคอลัมน์** เช่นช่อง `BI4` เก็บวันที่ หรือช่อง `วันที่End` เก็บคะแนน BI
  ระบบใช้เกณฑ์ว่าคะแนน BI ต้องเป็นจำนวนเต็ม 0 ถึง 20 เท่านั้น ถ้าเกินถือว่าเป็นวันที่ที่หลุดมา
- **ที่อยู่ถูกแปลงเป็นวันที่** เช่นบ้านเลขที่ `3/11` ระบบจะกู้กลับเป็นข้อความ
- **เบอร์โทรสองเบอร์ในช่องเดียว** จะถูกแยกเป็น `phone1` และ `phone2`
- **คำสะกดไม่ตรงกัน** เช่น `Recerrent stoke` แก้เป็น `Recurrent stroke`

กรณีที่ระบบเดาไม่ได้ เช่น `ยบ.IMC 11/11` ที่ไม่มีปีกำกับ จะไม่เดาให้
แต่บันทึกไว้ในแท็บ `migration_report` พร้อมบอกว่าเป็นแถวไหน ช่องอะไร ค่าเดิมคืออะไร
เพื่อให้เจ้าหน้าที่กลับไปตรวจกับแฟ้มจริง

## โครงสร้างข้อมูล

| ชีต | 1 แถวคือ |
|---|---|
| `patients` | ผู้ป่วย 1 ราย ใช้ HN เป็นกุญแจ |
| `bi_assessments` | การประเมิน BI 1 ครั้ง เก็บคะแนนราย 10 ข้อ ไม่ใช่แค่ผลรวม |
| `followups` | การติดตาม 1 ครั้ง (PT เยี่ยมบ้าน OPD โทรติดตาม) |
| `users` | ผู้มีสิทธิ์ใช้งาน |
| `summary` | มุมมองรวมหน้าตาใกล้เคียงไฟล์เดิม สร้างจากสูตรล้วน ห้ามพิมพ์ทับ |
| `migration_report` | จุดที่ต้องกลับไปตรวจกับแฟ้มจริงหลังนำเข้า |

ตารางแยกกันแบบนี้ทำให้บันทึก BI และการติดตามได้ไม่จำกัดจำนวนครั้ง
ต่างจากไฟล์เดิมที่มีช่องให้แค่ 5 ครั้ง ทั้งที่ฟอร์มกระดาษเผื่อไว้ 10 ครั้ง

## เกณฑ์ที่ระบบคำนวณให้

- **คะแนน Barthel Index** รวม 10 ข้อ เต็ม 20 คะแนน คิดสดขณะกรอก
- **เข้าโปรแกรม IMC** เมื่อ BI < 15 หรือ BI ≥ 15 ที่ติ๊กว่ามี multiple impairment
- **กลุ่ม CTF** ติดสังคม ≥ 12 / ติดบ้าน 5 ถึง 11 / ติดเตียง 0 ถึง 4
- **ครบ 6 เดือน** นับจากวัน Start ตาม `CONFIG.IMC_DURATION_DAYS` (183 วัน)
- **จำนวนครั้งที่ได้ PT** นับจากรายการติดตามที่ประเภทเป็น PT

## ข้อจำกัดที่ควรรู้

- Google Sheet ไม่ใช่ฐานข้อมูล ระบบใช้ `LockService` กันสองคนบันทึกชนกันแล้ว
  แต่ถ้าในอนาคตมีผู้ใช้มากขึ้นหรือต้องการ audit log เต็มรูปแบบ ควรย้ายไปฐานข้อมูลจริง
- ข้อมูลที่นำเข้าจากไฟล์เดิมมีเฉพาะคะแนน BI รวม ไม่มีคะแนนราย 10 ข้อ
  แถวเหล่านั้นจะมีหมายเหตุกำกับไว้ว่านำเข้ามา
- ชีต `summary` ตั้งใจให้ดูอย่างเดียว ถ้าพิมพ์ทับสูตรจะเสีย ให้แก้ผ่านแอปเท่านั้น
- ยังไม่มีฟังก์ชันพิมพ์ฟอร์มเป็น PDF เพราะทีมแจ้งว่าไม่ต้องใช้กระดาษแล้ว

## ใช้งานบนมือถือให้เหมือนแอป

Apps Script วาง `manifest` กับ service worker เองไม่ได้ เพราะหน้าจอจริงถูกฝังใน iframe
บนโดเมน `googleusercontent.com` ส่วนหน้าบนสุดเป็นของ `script.google.com` ซึ่งไม่ใช่ของเรา
เบราว์เซอร์อ่าน `manifest` จากหน้าบนสุดเท่านั้น ประกาศไว้ใน iframe จึงถูกเมิน
ส่วน service worker ต้องเป็นไฟล์ `.js` แยกบนโดเมนเดียวกัน แต่ `HtmlService` เสิร์ฟได้ทีละหน้า HTML

จึงแยกเป็นสองชั้น

### ชั้นที่ 1 — ในตัวแอปเอง (ใช้ได้ทันที ไม่ต้องตั้งอะไร)

- `WebApp.gs` ใส่ `apple-mobile-web-app-capable` ไว้ **iPhone / iPad** ที่กด
  ปุ่มแชร์ของ Safari → **เพิ่มไปยังหน้าจอโฮม** จะเปิดเต็มจอ ไม่มีแถบที่อยู่เว็บคร่อม
  (ใครเพิ่มไอคอนไว้ก่อนหน้านี้ต้องลบแล้วเพิ่มใหม่ iOS อ่านค่านี้ตอนกดเพิ่มเท่านั้น)
- เปิดแอปแล้วเห็นโครงหน้าจอทันที ไม่ต้องรอ `apiBootstrap` ที่กินเวลาหลายวินาที
- เน็ตหลุดแล้วขึ้นแถบเตือนค้างไว้ พร้อมบอกตรง ๆ ว่าที่กดบันทึกไปยังไม่ลงชีต
- **Android ไม่ได้อะไรจากชั้นนี้** Chrome เลิกใช้ `mobile-web-app-capable` ไปแล้ว
  ดู `manifest` อย่างเดียว ซึ่งใส่ไม่ได้

### ชั้นที่ 2 — เปลือก PWA ในโฟลเดอร์ `pwa/` (สำหรับ Android)

หน้า static เล็ก ๆ ที่ถือ `manifest` ไอคอน และ service worker แทนตัวแอป
เอาไปวางบน GitHub Pages แล้ว Android จะกด **ติดตั้งแอป** ได้จริง ได้ไอคอนจริง
เปิดแล้วเด้งเข้าลิงก์ `/exec` ให้เอง

เลือกวิธี **เด้งออกไปที่ลิงก์จริง** ไม่ใช่ฝัง iframe ไว้ในเปลือก เพราะแอปใช้อีเมลผู้ใช้
ตัดสินสิทธิ์ (`currentUser_` ใน `Api.gs`) ถ้าฝัง iframe การล็อกอิน Google จะต้องพึ่ง
third-party cookie ซึ่ง Safari บล็อกอยู่แล้ว เสี่ยงเข้าไม่ได้ทั้งที่ควรมีสิทธิ์
แลกกับการที่เปิดแล้วยังเห็นแถบชื่อเว็บบาง ๆ ค้างด้านบน

**วิธีเปิดใช้**

1. push โค้ดขึ้น GitHub ให้เรียบร้อย
2. ที่ repo บน GitHub เลือก **Settings → Pages → Build and deployment**
   ตั้ง Source เป็น *Deploy from a branch* แล้วเลือก branch `main` โฟลเดอร์ `/ (root)`
   (ไฟล์ว่างชื่อ `.nojekyll` ที่รากโปรเจกต์บอกให้ Pages เสิร์ฟไฟล์ตามที่เป็น
   ไม่ต้องเอา Jekyll มาแปลงก่อน ห้ามลบ)
3. รอสักครู่แล้วเปิด `https://manitsrik.github.io/Intermediate-Care-V0/pwa/`
4. บอกทีมให้เปิดลิงก์นั้นในมือถือ แล้วกดติดตั้งตามที่หน้านั้นบอก

**ก่อนใช้ต้องรู้** ลิงก์ `/exec` จะกลายเป็นของสาธารณะ เพราะฝังอยู่ในไฟล์ที่ Pages เสิร์ฟ
ตัวข้อมูลยังปลอดภัยเพราะ `currentUser_` โยน error ทิ้งทุกอีเมลที่ไม่มีในชีต `users`
แต่ต้องระวังว่า **ห้ามปล่อยให้ชีต `users` ว่างเปล่า** เพราะโค้ดถือว่ากำลังติดตั้งระบบอยู่
แล้วเปิดให้บัญชี Google ใดก็ได้เข้ามาเป็นผู้ดูแล

**เวลาแก้ไฟล์ในโฟลเดอร์นี้**

- แก้ลิงก์ปลายทาง แก้ที่ `APP_URL` ใน `pwa/index.html` ตัวเดียว
- แก้อะไรก็ตามใน `pwa/` ต้องขยับเลข `CACHE` ใน `pwa/sw.js` ด้วย
  ไม่งั้นเครื่องที่ติดตั้งไปแล้วจะยังเปิดของเก่าค้าง
- ทดลองบนเครื่องก่อนด้วย `node tools/serve-pwa.js` แล้วเปิด `http://localhost:8080`
  (ต้องเป็น localhost เท่านั้น service worker ไม่ทำงานบน `file://` และไม่ทำงานบน IP วงแลน)
- ไอคอนสร้างใหม่ได้เสมอด้วย `node tools/make-icons.js` ไม่ต้องเก็บไฟล์จากโปรแกรมวาดรูป

**ที่ยังทำไม่ได้แม้มีเปลือกแล้ว** คือใช้งานตอนไม่มีเน็ต ข้อมูลทุกอย่างวิ่งผ่าน
`google.script.run` ซึ่งต้องต่อเน็ตเสมอ เปลือกช่วยแค่ให้เปิดขึ้นมาแล้วเจอหน้าบอกสาเหตุ
แทนหน้า error ของเบราว์เซอร์

## ดูหน้าจอบนเครื่องก่อน deploy

มีสองวิธี ใช้คนละจุดประสงค์

### 1. พรีวิวบนเครื่อง — เร็วที่สุด ไม่แตะ Google เลย

```
node tools/build-preview.js
```

แล้วเปิด `preview/index.html` ในเบราว์เซอร์ ไม่ต้องมีเซิร์ฟเวอร์

ตัวพรีวิวประกอบจาก `css.html` กับ `js.html` ตัวจริง หน้าตาจึงตรงกับของที่ deploy
ส่วนฝั่งเซิร์ฟเวอร์แทนด้วยข้อมูลปลอม 6 เคสในหน่วยความจำ กดเพิ่ม แก้ ประเมิน BI
ได้ครบทุกหน้าจอ แต่ปิดหน้าต่างแล้วข้อมูลหายไป ไม่แตะ Google Sheet

เหมาะกับการดูดีไซน์ ทดลองกดใช้ และดูหน้าจอมือถือ (ย่อหน้าต่างหรือใช้โหมด
device toolbar ของเบราว์เซอร์) ไม่เหมาะกับการทดสอบตรรกะที่คุยกับ Google Sheet

### 2. ลิงก์ทดสอบของ Apps Script — ของจริงทุกอย่าง ยกเว้นทีมยังไม่เห็น

Apps Script สร้าง deployment ทดสอบไว้ให้ตั้งแต่ต้น ลิงก์ลงท้ายด้วย `/dev`
แทนที่จะเป็น `/exec` ดูรหัสได้จาก

```
npx @google/clasp list-deployments
```

ตัวที่ขึ้น `@HEAD` คือ deployment ทดสอบ ลิงก์คือ
`https://script.google.com/macros/s/<รหัสนั้น>/dev`

- แสดงโค้ดล่าสุดเสมอทุกครั้งที่ `clasp push` โดยที่ลิงก์ `/exec` ของทีมไม่ขยับ
- เปิดได้เฉพาะบัญชีที่มีสิทธิ์แก้ไขสคริปต์
- **ใช้ Google Sheet ใบเดียวกับตัวจริง** กดบันทึกแล้วข้อมูลลงชีตจริง

### ลำดับการทำงานที่แนะนำ

1. แก้โค้ด แล้ว `node tools/build-preview.js` ดูหน้าตาก่อน
2. `clasp push` แล้วเปิด `/dev` ทดสอบกับข้อมูลจริง
3. พอใจแล้วค่อย `clasp create-deployment --deploymentId <รหัสเดิม>` ทีมถึงจะเห็น
